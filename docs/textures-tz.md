# ТЗ: замена PNG на процедурные текстуры

Документ для продолжения работы. Проект: боковой стрелковый шутер (Phaser 3),
папка `project` на рабочем столе. Стиль: чёткая рисованная графика кодом
(как ящики, персонаж, пончик) — НЕ живопись, НЕ фото.

## 1. Зачем

- Скорость загрузки (было: 52 здания на 52 МБ + десятки артов карт).
- Память GPU/текстуры.
- Вариативность: кодом проще плодить разновидности, чем рисовать PNG.
- Единый стиль игры.
- PNG оружия — НЕ ТРОГАТЬ (решение владельца).

## 3. Железные правила (нарушишь — получишь баг)

1. **TileSprite НЕ умеет DynamicTexture.** `RenderTexture.saveTexture()` кладёт
   именно её — движок молча подменяет на зелёный `__MISSING` (так был зелёный
   фон на всех уровнях). Печь только в статику: `textures.createCanvas()` +
   2D-контекст + `refresh()`, либо `graphics.generateTexture()`.
2. **Ключи текстур стабильны.** Карты (`maps/*.json`) и сейвы уровней хранят
   КЛЮЧИ, не файлы. Менять пиксели под ключом можно, переименовывать ключи —
   только с алиасом (пример: `BLD_ALIAS`, `resolveBuildingTex`).
3. **Версии ассетов `?v=N`.** В идеале — одним числом на всё дерево, бампить
   разом при любом изменении арта/кода (иначе браузер отдаст кэш).
   Практика: коллега ведёт параллельную нумерацию — тогда бампим точечно
   только цепочку до изменённого файла (файл → импортёр → … → `index.html`)
   числом выше всех, дерево целиком не трогаем.
4. **HiDPI-текст:** базовый скейл текста 0.5 (`js/game.js`). Мерить только через
   `displayWidth/displayHeight`. Твины скейла — относительные (0.5→0.535),
   иначе текст прыгнет в 2x. Графику с абсолютными координатами в скейл-твины
   не ставить.
5. **Фолбэки через `textures.exists()`.** Любой потребитель рисованного арта
   обязан иметь ветку «нет текстуры» (прямоугольник/пропуск), без throw.
6. **Контейнеры:** контент добавлять в панель (`c.add(content)`), иначе висит
   на глубине 0 и не виден. Маски + `scrollFactor(0)` внутри контейнеров
   проверять скриншотом (в canvas-рендере капризны).
7. **Детерминизм:** вся процедурная живопись — через seeded RNG
   (`mulberry32(hashStr(...))`), иначе фон/полосы «плывут» между матчами.
8. **Производительность:** вектор каждый кадр — дорого. Статику — запекать
   (`generateTexture`), динамику (тексты/кнопки) — виртуализировать окном.
   Ориентир: окно контрактов было 800 объектов/5 FPS → стало ~70/35 FPS.
9. **Масштаб рисованного:** холсты декора показываются высотой 200–300 при
   персонаже 90 — деталь 1/3 человека ≈ 8–12px холста (было: колесо
   с персонажа ростом; чинилось дважды). Проверять: показать холст
   целиком и сравнить с 90.
   ✅ АУДИТ 13.10.2026 (всего нарисованного): земля 1:1 (камешки 5–11) ✓;
   ящики/бочки ~1:1 (заклёпки 2–4) ✓; стены/сетка/ежи (болты 4, ячейки 14,
   балки плоские) ✓; здания: окна 40–60, двери 50–85 ✓; кейсы/подборы/ракета
   мелкие ✓; панорама: зерно 7–32, архитектура крупная как положено ✓.
   Нарушителей не осталось (колесо/шина/холмы починены).
10. **Низ холста = земля:** арт декора обязан доходить до нижнего края
   (щебень/цоколь во всю ширину). Было: у scrap/ruin/ruin2 внизу 16–20px
   прозрачности — баррикада visibly висела над травой (Форты); у wreck
   центр ужатия был выше колёс — машина парила. Проверять: показать холст
   целиком, низ без дыр. Аудит всех низов пройден (18/18 численно ≤ sink,
   герой панорамы притоплен + тень — парить нечему).
11. **Оружие, звуки, баланс, геймплейная логика** — не трогать без отдельного
    поручения. Только внешний вид.
12. **Одинаковый декор — не клонировать (15.10.2026, карта «Форты»).**
    Один и тот же ключ (`map_ruin`, `map_scrap`, …) в пределах одного прохода
    декора (`addModeDecor`, `buildBomb/Koth/SkirmishArena`) ставится НЕ БОЛЕЕ
    одного раза — даже в другом размере (джиттер ±10%) или зеркально
    (`setFlipX`): глаз мгновенно цепляет копию и «разнообразие» рассыпается.
    Как делать: `pickDecor(scene, pool, used)` со сквозным `used = new Set()`
    на весь проход (оба ряда + края); пулы — без весовых дублей
    (вес — размером пула, не повтором ключа); если пул исчерпан —
    `pickDecor` сам разрешает повтор, чтобы не оставлять дыру.
    Джиттер размера и зеркалка разрешены только для ОДИНОЧНЫХ экземпляров
    (разные арты — чуть разный размер, безтекстовый арт — flip).

## 4. История болезни «зелёный фон» (чтобы не повторить)

Симптом: фон в зелёную полоску/квадраты на всех уровнях + новые текстуры
«не подключились». Причины было две:
- `bakePngHouseLayers` пёк полосы в `RenderTexture.saveTexture()` =
  DynamicTexture, а `TileSprite` такие не умеет → движок подменял на зелёный
  `__MISSING` во всю ширину уровня. Лечится только статикой (п.3.1).
- 5 ключей `map_*` ссылались на несуществующие файлы (404) — декор молча
  пропускался. Лечится привязкой ключей к существующим файлам/коду.

## 6. Как проверять работу (чеклист)

- Игра стартует без ошибок в консоли (F12), меню открывается.
- Скрин уровня с новым артом: кампания + режимная карта (`maps/*.json`).
- Редактор: палитра зданий показывает миниатюры, здание ставится/сохраняется.
- Старые кастомные уровни с `bld_*` открываются (алиас), серых боксов нет.
- FPS окна/уровня не просел (ориентир — замеры до/после).
- Тестовые файлы: `auto.html` — в работе (автотесты коллеги), не удалять;
  чужие процессы и вкладки браузера не трогать (коллега дебажит параллельно).
